## Local protections and lifecycle observations

- Compose `minio-init` creates `reals-media` and sets anonymous access to `none`. A separate disposable MinIO container, bucket and synthetic text object confirmed anonymous GET 403, signed GET 200, and signed GET 403 after a 10-second signature expiry. Deleting the object returned 404 for a still-valid signed URL. These checks used no application media or credentials. The storage signer uses `Duration.ofMinutes(signedUrlDurationMinutes)`; local/dev/prod configuration defaults to 15 minutes. Production startup rejects public read mode. Signature expiry is a storage check; sign-out, blocking or suspension do not invalidate an issued bearer URL by themselves.
- Phase 1's backend hardening omits counterpart AUDIO from blocked ordinary history and rejects blocked audio HEART replay before signing. Text, own audio and privileged administrative evidence keep their separate policies. Focused backend tests rechecked this baseline (results below). A block denies new partner visual-photo issuance through the visual access policy. Suspension-related issuance and a race across block commit and response serialization were not exercised here. Deletion removes bytes only after storage deletion actually completes.
- Web signed media is rendered as image or audio URLs without writing them to application localStorage or sessionStorage. The only explicit object URL in chat is the local recorder draft; `AudioComposer` revokes it on replacement/disposal. `MessageAudio` removes its element and source on unmount, and stops on tab hide. Session sign-out clears the account/profile snapshot; identity and ownership transitions have existing abort/retirement controls. A retained mounted chat or browser cache still needs explicit revocation validation. Firebase Auth's configured local/session persistence contains authentication state and is separate from app media persistence.
- No application use of IndexedDB, Cache Storage or service worker registration was found in Web source. This source inventory does not prove the absence of browser HTTP cache or third-party SDK storage. The Web Pages `_headers` sets `Referrer-Policy: strict-origin-when-cross-origin`; media elements use `referrerPolicy="no-referrer"` where inspected. Signed URLs remain bearer capabilities and may appear in browser network tooling.
- Android logging is `BASIC` only for non-production debug builds and redacts Authorization, Cookie, Set-Cookie and App Check headers; production is `NONE`. No Web analytics SDK or explicit media URL console logging was found in reviewed source. Backend exception logging and hosted ingress/storage/CDN/analytics pipelines were not inspected at runtime. No claim of hosted log cleanliness follows from source review.

The local MinIO run did not fetch application-generated 15-minute URLs through a real authenticated backend, and a 10-second `mc` signature establishes provider behavior rather than the app's exact TTL. No end-to-end Firebase identity, browser disk cache inspection, browser Cache Storage/IndexedDB inventory after authenticated use, device Coil cache replay, CDN/R2 cache header, hosted bucket policy, hosted access log or hosted expiry was tested. Repeat the anonymous/signed/expired/deleted GET matrix against a disposable hosted bucket and synthetic object; inspect sanitized response headers and metadata at every CDN hop. Use two synthetic authenticated accounts in a disposable backend/browser setup to inspect storage and cache across sign-out, account replacement, tab transfer, reload, block and suspension, including playback already in progress. Capture only status codes, policy headers and redacted URL structure.

Android's `ProfilePhotoImageRequests` sets Coil disk and memory keys through `stableProfilePhotoCacheKey`, which strips the signed query and uses photo ID plus path without account identity. Cache reuse after URL renewal is expected from this design; cross-account collision or visible disclosure is a **potential risk**, unverified on a device. Verify cache eviction and account separation with two synthetic identities and photos. The Web browser script's synthetic fixture failure likewise leaves tab transfer behavior unverified in this assessment.

## Remediation order

1. Reconcile authoritative blocked history in both clients: remove only counterpart AUDIO after a complete authoritative snapshot or explicit block state, stop/release its player, reject late reads and URL renewals, and preserve text, own audio and administrative evidence. Cover initial/incremental pages, pagination gaps, overlapping responses, resume, sign-out and identity replacement.
2. Define private media cache policy at upload and hosted delivery. Validate response headers and browser/Coil eviction behavior with synthetic objects before choosing `no-store`, a bounded private lifetime or account-scoped keys. Address already cached objects and URL-bearing logs.
3. Validate storage/CDN and hosted log redaction in a disposable hosted environment, including the exact 15-minute application signature and issuance after block, deletion and suspension. Consider shorter TTL or revocation mechanisms only with measured UX and infrastructure behavior.

No production remediation was made. The local storage conclusions apply only to the disposable MinIO instance; hosted R2, CDN, ingress and browser/device cache conclusions remain open.
